# Uncles in Space — Website Visual System Specification

**Document type:** Companion specification  
**Register:** Uncles in Space (UIS)  
**Version:** v01

## Governing principle

The supplied final mockup is the **visual source of truth**.

## Canvas

The desktop presentation must retain the reference’s compact document-like canvas.

Explicitly control:

- maximum content width
- left margin
- right margin
- gallery/content alignment
- main image/content proportions
- text measure
- vertical rhythm

Do not allow large desktop viewports to produce a stretched contemporary blog.

## Background

Use the final **grayer off-white** page background rather than pure white.

Gallery tiles retain their own reference-specific background colors.

## Header

**UNCLES IN SPACE**

Use the rocket icon from the reference.

Subtitle:

**A TAXONOMIC WORLDBUILDING SERIES**

## Navigation

**ENTRIES · ABOUT UNCLES IN SPACE · ABOUT MOBY OTOMO · FUTURE WORKS**

Keep it subordinate to the title.

## Gallery

The gallery is at the top of the content area.

There is no left-hand navigation/article panel.

It should be:

- compact
- horizontal
- individually colored
- unlabeled
- horizontally scrollable

## Main entry composition

Preserve the reference’s main image + text composition.

Do not reduce the main image merely to create whitespace.

## Main image standardization

Use a consistent display frame/bounding box so source-image differences do not create accidental visual scale differences.

Normal Uncle characters share a standardized height/pose system.

**Mr. Papi (No. 11188)** is an intentional smaller-stature exception. Preserve his canonical proportions; do not artificially stretch him.

## Phrase / explanation / Meaning hierarchy

Preserve:

```text
phrase
↓
Chinese/explanation box
↓
Meaning:
↓
large Meaning statement
```

The explanation box belongs below the phrase.

The Meaning statement belongs under “Meaning:”.

Reference statement:

**Uncle Who Clarifies Until Nothing Remains Unclear Or Finished.**

Retain its distinctive serif treatment, scale, and prominence.

## Typography

Preserve the reference hierarchy between title, labels, phrase, explanation box, Meaning label, large Meaning statement, and essay body.

Do not flatten everything into one generic modern font hierarchy.

## Color

Use a restrained dark neutral for principal text.

Orange remains an accent for applicable labels/details.

Do not make orange the default body text.

## Borders and document details

Preserve fine-line archival/document details where they are part of the reference. Keep them delicate and subordinate; do not turn them into heavy UI cards.

## Density

Compactness is a feature. Avoid excessive padding, giant hero sections, oversized navigation, large empty margins, unnecessary cards, and oversized footer areas.

## Responsive behavior

On smaller screens:

- preserve hierarchy
- keep gallery horizontally scrollable
- reflow the main entry as necessary
- preserve image proportions
- preserve readable text measure
- retain archival/document character

Mobile is an adaptation, not a redesign.

## Footer

Use restrained publication-footer typography with real project links, including:

- Twitter / X
- GitHub
- YouTube
- Instagram
- Substack, if active

## Exclusions

Do not introduce:

- left sidebar
- full-width layout
- modern dashboard styling
- generic blog cards
- excessive whitespace
- “Read Full Entry”
- “Older Entries”
- FIELD LOG JOURNAL ENTRY
- GU-ARCHIVE 13333
- visible gallery labels
- unnecessary decorative redesigns
